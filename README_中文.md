# TokenDesk · macOS + Windows

TokenDesk 是面向 macOS 与 Windows 的 ChatGPT Work / Codex 剩余额度与运行任务监控器。

主数据链路只有一条：

**Chrome 后台主动查询 → 本机 TokenDesk → 菜单栏 / 浮窗 / 额度历史**

### 任务开始、结束、完成提醒响应更快（扩展 v1.8.17）

- 任务开始：在浏览器发出 ChatGPT `conversation POST` 请求时立刻产生开始事件，不必等待服务器先返回 SSE 响应头；GET 浏览历史不会误判为生成。页面控件变更检测从 250ms 优化到 100ms，活动心跳 5s→2s。
- 任务结束：服务器 SSE 正常关闭时实时上报结束并核查页面；没有确切网络结束信号时，前台 UI 缺少运行依据的缓冲窗口从 45s 缩短至 3s（后台页面保留 15s 容忍节流）；不将未确认的断线标注成“已完成”。禁用状态的“停止”按钮不再当作仍运行的证据。
- 后台到桌面：任务开始、结束、阶段或模型字段变动时立即推送快照，减少 120ms 防抖并行等待统计队列的延迟；仍串行提交快照避免旧状态覆盖新状态。
- 系统完成提醒：稳定确认缓冲从 2.5s 调整为约 0.9s。恢复运行、切换对话和关闭标签页仍会取消通知，同一轮任务只提醒一次。
- 此版本只需更新 `Chrome_Extension`；Windows v1.2.13 与 macOS v1.8.10 不必重新安装。页面渲染或 Chrome 进程完全冻结、以及未公开终止状态的云端 Work 子任务，仍不能保证实时确认。

### 部分任务识别模型、部分不识别（扩展 v1.8.16）

旧版网络脚本只缓存最后一条模型信号，多个对话同时运行、交替切换时，新请求可能覆盖旧对话缓存。v1.8.16 改为按对话路径缓存模型元数据，保持服务器确认模型优先于请求时所选模型，并修复 `fetch(Request)` 请求备用模型信号未带对话路径的问题；跨对话模型不会串用。补充两个对话不同模型、切换后仍能各自恢复和不泄漏聊天正文的自动测试。

此修复只需覆盖 `Chrome_Extension` 并重新加载，Mac / Windows 桌面端不需要重新安装。即使新版本通过测试，Work 内部任务如果没有在网页网络请求中提供可验证模型标识，仍会显示“未识别（未收到模型标识）”，不能根据当前模式猜测真实执行模型。使用扩展的“检查模型识别”区分未捕获请求与服务器未提供模型。

### Mac 工作任务模型栏不显示（扩展 v1.8.15）

Mac v1.8.10 桌面端在未收到模型字符串时隐藏模型字段，造成“任务有运行时间却没有模型栏”。Chrome 扩展 v1.8.15 会在无模型元数据时发送明确占位文字 **模型：未识别（未收到模型标识）**，而不虚构模型。若收到真正的 `resolved_model_slug` 或请求中明确的模型，则显示相应模型并保留来源区别。只需升级浏览器扩展，不需要重新安装 Mac 或 Windows。若 Work 内部任务未在网页网络中公开实际执行模型，不能凭页面状态推断它使用哪个模型。请通过扩展菜单的“检查模型识别”检查连接、请求次数、SSE 和模型来源。

### 任务完成后系统提醒（浏览器扩展 v1.8.14）

- Chrome / Edge 扩展默认启用“任务完成时提醒我”，可在 TokenDesk 扩展弹窗取消勾选。
- 只有同一任务曾处于运行状态、对应 `conversation` 网络事件流正常关闭且页面确认不再执行，才会等待约 2.5 秒发送系统通知：**“ChatGPT 任务已完成”**、**“任务已完成，注意查看。点击打开对应对话。”**。继续运行、切换对话或关闭标签页会取消待发送通知。
- 同一轮任务最多提醒一次；已发过的提醒记录在本机保存约 48 小时，浏览器扩展重启后也可防重复。
- 点击通知优先切回原始 ChatGPT 标签页；原标签页已关闭时，新建标签页打开原对话。通知内容不会暴露聊天标题或正文。
- 此功能使用 Chrome / Edge 的系统通知权限，请确认浏览器与 Windows / Mac 系统允许通知。如果网页无法确认任务已完成（例如浏览器关掉后仍在云端运行、Work 子任务没有结束事件），**不保证收到通知**，也不会将“待确认”误认为“已完成”。
- 只需升级 `Chrome_Extension` 至 v1.8.14，不需要重复安装 Windows v1.2.13 或 macOS v1.8.10。

### 长时间 Thinking / Working 掉线修复（扩展 v1.8.13）

旧版仅凭停止按钮 / 最新消息的状态节点判断任务，页面重绘时可能误判结束；浏览器后台心跳超过 45 秒也会过早过期。v1.8.13 增加同一对话的 SSE 网络流打开 / 关闭状态跟踪，并在获取模型字段后继续监听流结束（不储存后续聊天正文）；短暂没有状态节点时保留最近的运行证据，后台心跳容忍延迟增至 150 秒。Chrome 扩展诊断现显示“当前对话网络流：正在接收 / 已结束 / 未确认”。测试覆盖长流持续、结束、重绘以及跨对话隔离。

这套修复只需要更新 Chrome_Extension 文件夹，并重新加载扩展、刷新 ChatGPT；Windows v1.2.13 桌面端桥接协议不变。**如果网页或 Chrome 渲染进程完全冻结，扩展无法验证云端是否还在运行，必须将其视为状态未确认，不应假装仍在生成。** 旧 Windows 桌面端对未确认任务的呈现仍有限制，需要后续桌面端单独修正。

### 模型识别调试（只更新扩展，不必重装桌面程序）

- 桌面端 Windows v1.2.13 / macOS v1.8.10 的 `/tasks` 桥接字段不变。网页模型识别修复通常只需更新 Chrome 扩展。
- 从 GitHub Actions 的 **Verify and package TokenDesk extension** 下载最新的 `TokenDesk-Chrome-Extension` 工件，解压到临时文件夹。
- **保留原来的 Chrome_Extension 文件夹路径**，将新工件文件覆盖到这个现有文件夹里，不要删掉旧扩展后创建一个新路径（避免扩展 ID 及本地配对/统计记录变化）。
- 打开 `chrome://extensions`，在 TokenDesk 卡片点击**重新加载**，确认版本号，之后对打开的 ChatGPT 网页按 `Ctrl + Shift + R` 刷新。
- 发送一条**新的** ChatGPT 消息，打开 TokenDesk 扩展的**检查模型识别**。新诊断会显示主世界网络监听是否连接、`fetch` 是否仍由扩展接管、SSE 流次数和模型来源。
- 如果网络监听未连接或未捕获新的请求，请把扩展诊断截图发来；无需重新安装桌面端。模型检测依赖 ChatGPT 非公开网页数据，不保证每个 Work 子任务都提供模型字段。
